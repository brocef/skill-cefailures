# v1.5.0

## Added
- Namespaced orchestrator identities: `@orchestrator/<scope>` replaces the v1.4.0 singleton `orchestrator`. Multiple orchestrators can coexist on one broker host, each with a distinct scope name. Scope must match `[A-Za-z0-9][A-Za-z0-9._-]{0,63}` (must start with an alphanumeric; up to 64 chars total).
- Authority hierarchy convention in the broker skill: `SKILL.md` gains Critical rule #5 ("Weigh DMs by sender authority") pointing at a new `skills/broker/docs/authority.md` with the full prose. Order is `user` > `@orchestrator/<your-scope>` > peer agents; on conflict, relay upstream. The hierarchy is conventional — no auth enforcement.
- `.broker/config.json` per-cwd identity pinning. Walk-up lookup (stops at `$HOME`) sits between the `--identity` flag and cwd-derivation; symlinks resolve normally; malformed JSON warns and falls through. New `broker init [--identity X] [--force]` subcommand creates the file in the current directory only (does not walk up).
- `BROKER_IDENTITY` env var is honored as a fallback when `--identity` is omitted, with the same orchestrator-shape validation as `--identity` and `.broker/config.json`.
- `--show-ids` flag on `broker read` / `broker history` / `broker follow`. Prefixes each emitted line with the message ID (10-char column + 2-space gutter), letting recipients run `reply-all --to-message <MID>` without rummaging through `send` stdout. Legacy lines (pre-v1.5.0) render an em-dash placeholder.
- CLI-level `--identity` validation rejects `@orchestrator`, `@orchestrator/`, `@orchestrator/.`, `@orchestrator/-foo`, and any `@orchestrator/<scope>` whose scope contains invalid characters or exceeds 64 chars. The check fires at parse time, before connect, so typos surface as a clear argparse error.
- `ORCHESTRATOR_RE` is a public symbol on `broker_constants` so the CLI validator and other consumers can use it without a private-name reach.
- `.broker/` added to `.gitignore`.

## Changed
- **Breaking:** bare `orchestrator` identity is no longer reserved. It now connects as a peer (no special handling).
- **Breaking:** inbox and outbox log files now write `<MID>\t<line>` per entry. Existing files (pre-v1.5.0) remain readable — `split_mid_prefix()` detects them by the leading character (digit = legacy timestamp, `m` = MID prefix).
- `_handle_history_inbox` strips the MID prefix before passing each line to `parse_message` for `--from`/`--since` filtering (downstream of the wire-format change).

## Removed
- `--token` CLI flag from all subcommands (`server`, `send`, `broadcast`, `reply-all`, `read`, `follow`, `history`, `clients`).
- `BROKER_TOKEN` env var — no longer read.
- `BrokerServer._read_token` method — token-file lookup no longer exists.
- `is_reserved()` predicate from `broker_constants` — no longer needed; `BROADCAST` is the only permanently unclaimable identity and is checked directly at the connect site.
- `RESERVED_IDENTITIES` constant from `broker_constants` — only `BROADCAST` and `ORCHESTRATOR_RE` remain.
- `~/.mcp-broker/tokens/` directory is no longer read or written. Delete it if you want to clean up.
