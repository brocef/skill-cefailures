# v1.5.1 — broker identity resolution: closest source wins

## Identity resolution: closest source wins

`broker whoami` had a sharp edge in monorepo-style layouts: with `/org/.broker/config.json` pinning `@org` and `/org/projectA/package.json` naming `@org/projectA`, running `broker` from `/org/projectA` returned `@org` instead of `@org/projectA`. The resolver was walking up to `$HOME` looking for `.broker/config.json` *before* it ever consulted `package.json`, so a parent's pin shadowed the project's own name.

Resolution now walks up one directory at a time, checking *both* `.broker/config.json` and `package.json` at each level. The closest source wins:

- `/org/projectA` → `/org/projectA/package.json` → `@org/projectA` ✓
- `/org/projectA/src/utils` → walks up, first hit is `/org/projectA/package.json` → `@org/projectA` ✓ (this was also broken before)
- `/org` → `/org/.broker/config.json` → `@org` ✓ (unchanged — there's no nearer `package.json`)

Same-directory ties still go to `.broker/config.json` — it's an explicit pin, and projects that need to override their own `package.json` name keep doing so by dropping a config file alongside it.
