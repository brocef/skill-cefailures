# v1.7.1

## Documentation Sync skill

- New `Follow-ups` pattern: projects can now opt into a `docs/FOLLOWUPS.md` standing log that tracks deferred code-related work after feature implementations. The skill describes the entry format (work title, commit range, branch name, date), what counts as a follow-up vs. what doesn't, and the lifecycle of adding entries on new work and annotating items as completed (strikethrough + completion date) when they're finished, so the historical record is preserved across versions.
- Version-bump guidance is now sized-based and pragmatic rather than strict SemVer. `patch` is the default for most work — bug fixes, refactors, small features, doc updates. `minor` covers medium-sized change sets and may include some scoped reverse-incompatible changes. `major` is reserved for extremely large change sets, sweeping rewrites, broad reverse-incompatible work, or dropped support — still only when the user explicitly asks for it.
- Setup flow now creates the tracked folders and files when they don't already exist. When you ask Claude to add a Documentation Sync section to a fresh project, it will now also create `docs/release-notes/` and `docs/changelogs/` (with empty `upcoming.md` files inside each) and, if the Follow-ups pattern is adopted, a `docs/FOLLOWUPS.md` with its standard header — so the agent has somewhere to write on the first trigger fire instead of failing on a missing path.
