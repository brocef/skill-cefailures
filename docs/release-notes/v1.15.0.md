# Upcoming

## Added

- A new `report` skill for sending feedback about this plugin back to its maintainer. If a skill gives wrong guidance, a slash command misfires, or you have a feature idea, it points you at https://github.com/brocef/skill-cefailures/issues and hands you a fill-in-the-blanks skeleton for a bug or a suggestion — including the details that make a report actionable (which surface you hit, which agent you were running, the plugin version).

## Removed

- The `/skill-cefailures:process-inbox` and `/skill-cefailures:process-inbox-initiative` commands are gone. They were built around a `docs/inbox/` folder convention that is no longer in use; cross-repo change requests now route through TCW (`tcw work delegate` / `tcw work escalate`, adopted via `docs/work/inbox/`). If you relied on the `docs/inbox/` workflow, use the TCW work axis instead.

## Improved

- The `/skill-cefailures:brain-style:claude-md` command now checks how *often* a fact changes, not just where it's defined. It flags volatile content that goes stale on ordinary PRs — exact dependency pins, "Status" / "current phase" sections, deep file paths that move on refactor, and long checklists only some tasks need — and tells you where each belongs instead. The test to apply: "would a routine PR make this line wrong?"
