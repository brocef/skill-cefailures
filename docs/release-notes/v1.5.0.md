# v1.5.0 — broker namespacing, authority hierarchy, and ergonomic polish

This release builds on v1.4.0's DM-only refactor with five threads: namespaced orchestrator identities, an authority hierarchy convention in the broker skill, per-workspace identity pinning, an opt-in message-ID column on read, and a deliberate simplification of the auth model (no more token gate).

## Namespaced orchestrators

The single reserved `orchestrator` identity is replaced by `@orchestrator/<scope>` — multiple coordinators can coexist on one broker host, each with a distinct scope name. Scope must match `[A-Za-z0-9][A-Za-z0-9._-]{0,63}` (must start with an alphanumeric; up to 64 chars total of letters, digits, dot, underscore, hyphen).

```bash
broker server --identity @orchestrator/myorg
```

CLI argparse rejects malformed orchestrator names (`@orchestrator`, `@orchestrator/`, `@orchestrator/with spaces`, `@orchestrator/.`, `@orchestrator/-foo`, etc.) at parse time so typos surface clearly instead of silently downgrading to peer mode.

## Authority hierarchy

`skills/broker/SKILL.md` adds Critical rule #5: agents should weigh DMs by sender authority (`user` > `@orchestrator/<your-scope>` > peer agents) and relay conflicts upstream rather than silently complying. Full prose lives in `skills/broker/docs/authority.md`.

The hierarchy is conventional only — the broker does not authenticate any identity. This is deliberate for the local-only threat model.

## `.broker/config.json` and `broker init`

Pin a workspace's identity once instead of passing `--identity` everywhere:

```bash
cd ~/code/projectA
broker init --identity @myorg/projectA   # writes .broker/config.json
broker send --to bob "hello"             # uses @myorg/projectA without --identity
```

Walk-up lookup stops at `$HOME` so a stray config in `/` doesn't leak into every workspace. Malformed JSON or missing/invalid `identity` field warns on stderr and falls through to the cwd-derivation rule. `BROKER_IDENTITY` env var is honored between the explicit flag and the config file.

`broker init` writes `.broker/config.json` in the **current directory only** — it does not walk up to find a parent config. To update an existing pinned workspace, edit its config file directly. `.broker/` is added to the project's `.gitignore`.

## `--show-ids`

`broker read --show-ids`, `broker history --show-ids`, and `broker follow --show-ids` prepend the message ID to each line:

```
$ broker read --show-ids
msg-7f3a91  2026-04-30T18:21:09Z [alice] hello bob
msg-c042bf  2026-04-30T18:23:44Z [carol → you, bob] question for the team
—           2026-04-29T11:02:11Z [legacy-sender] pre-v1.5.0 message with no MID column
```

Default off; the existing format is unchanged. Legacy inbox/outbox lines (pre-v1.5.0, no MID column on disk) render an em-dash placeholder.

## Removed: token mechanism

`--token` and `BROKER_TOKEN` are gone. Reserved identities (`@orchestrator/<scope>`, `human`) are no longer authenticated by the broker; they're conventional names that gain authority via the hierarchy in `docs/authority.md`.

The broker is local-host-only. Token files were plaintext on disk in user-readable directories — anyone who could read them could also pass them as `--token`. The gate added CLI surface, ~50 lines of code, ~12 tests, and several doc sections without meaningful security benefit for the threat model. Authority is now conveyed entirely by convention.

If a process was relying on the token to prevent identity collisions, switch to distinct scope names: instead of two orchestrators sharing `@orchestrator/myorg` with different tokens, use `@orchestrator/myorg-staging` and `@orchestrator/myorg-prod`.

## Breaking changes

Action required for v1.4.0 users:

- **`--token` and `BROKER_TOKEN` are removed.** Drop them from any `broker` invocations and from your environment.
- **Bare `orchestrator` identity is no longer reserved.** It now connects as a peer (no token, no special handling). Migrate to `@orchestrator/<scope>` — e.g. `@orchestrator/default` if you don't need multiple coordinators.
- **`is_reserved()` and `RESERVED_IDENTITIES`** are removed from `broker_constants`. Only `BROADCAST` and `ORCHESTRATOR_RE` remain. Anything that imported the predicate must inline its own check (or drop the check — the broker doesn't enforce it anymore).
- **Inbox/outbox wire format gains a MID prefix.** Lines now write `<MID>\t<line>`. Existing pre-v1.5.0 files remain readable; `split_mid_prefix()` detects them by the leading character (digit = legacy timestamp, `m` = v1.5.0+).
- **`~/.mcp-broker/tokens/` is no longer used.** Delete the directory if you want to clean up.

Full migration in one shell snippet:

```bash
# v1.4.0 → v1.5.0
rm -rf ~/.mcp-broker/tokens
unset BROKER_TOKEN
broker server --identity @orchestrator/default     # was: --identity orchestrator --token X
```
