# v1.4.0 — broker DM-only refactor + reserved-identity tokens

## Broker

This release removes the room-based broker model entirely. The deprecation warnings on `create` / `join` / `leave` / `close` / `members` / `list` / `repl` are replaced by argparse rejecting them outright — the DM model is now the only model. Every participant has a per-identity inbox; senders address recipients by their cwd-derived identity (or a reserved one); reply-all reconstructs the recipient set from the original message record.

### What's gone

- Subcommands: `create`, `join`, `leave`, `close`, `members`, `list`, `repl`.
- API methods on `BrokerClient`: `create_conversation`, `send_message`, `join_conversation`, `leave_conversation`, `history` (room form), `list_conversations`, `list_members`, `close_conversation`, plus the `_push_buffer` and `get_new_messages` machinery that fed room-push consumption.
- Server handlers for the equivalent request types and all the per-room state (`conversations`, `members`, `_load_from_disk`, `_save_conversation`, `_join_member`, `_broadcast_system`).
- `~/.mcp-broker/conversations/` is no longer read or written. Existing files are dead and safe to delete.

### What's new

`broker server` is now a useful interactive surface. The REPL is DM-aware:

```
broker> who
  alice
  projectA-server
  user (you)

broker> send projectA-server please publish v1.2.3
  sent msg-7f3a91

broker> broadcast pausing publishes — npm registry is down
  broadcast msg-b12c04 to 4 identity(s)

broker> emit-messages on
# every routed message now also prints inline as [audit] <line>
```

`broker clients` adds a one-shot equivalent to `who` for scripts.

The reserved-identity token mechanism is now end-to-end. `--token <value>` (or `BROKER_TOKEN` env) plumbs through `BrokerClient.connect()` and through every CLI subcommand, including `broker server` for orchestrator-mode REPLs. Previously the server enforced the token file but the client had no way to send one, so `orchestrator` could never connect; that's fixed.

A related bug is fixed: when a client tried to connect as a reserved identity without a valid token, the rejection escaped the asyncio connection callback as `Unhandled exception in client_connected_cb`. The connect handler now catches the rejection and returns a clean error response.

### Breaking changes (action required for existing installs)

- `BrokerServer(storage_dir=…)` → `BrokerServer(root_dir=…)`. The argument is now the broker root (`~/.mcp-broker/`), not the conversations subdir.
- `MCP_BROKER_STORAGE` env var → `MCP_BROKER_ROOT`. CLI flag `--storage-dir` → `--root-dir`.
- Any code calling the room API (`broker create`, `broker.send_message(...)`, `_handle_create`, etc.) must move to the DM equivalents:
  - 1-to-1 chat → `broker send --to <identity>`.
  - Multi-party with structured replies → `broker send --to a,b,c` + `broker reply-all --to-message <MID>`.
  - "List who's around" → `broker clients` (live presence) or `broker history` (inbox-side view).

If you have data in `~/.mcp-broker/conversations/` from prior versions and you don't need it, delete the directory:

```bash
rm -rf ~/.mcp-broker/conversations
```

### Health check

The README quickstart now leads with the AI-assisted setup: ask Claude "check broker setup" and the broker health-check skill will diagnose `~/.local/bin` on `$PATH`, the `broker` symlink, server reachability, the broker Bash permission, and version drift, then offer to apply the auto-fixable ones. The manual symlink + permission steps are still documented for users who want them.

Check 4 also got a small accuracy fix: it now accepts either `Bash(broker:*)` (tool-name form) or `Bash(broker *)` (command-prefix form) as a valid permission entry. Previously only the colon form passed, which produced spurious `✗` results on installs that had used the prefix-pattern syntax.
