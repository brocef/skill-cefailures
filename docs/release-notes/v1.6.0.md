# v1.6.0 — Broker Mode; `recv` replaces `follow`

## Broker Mode

A new `/broker-mode` slash command turns an agent into a message-driven
participant. The command runs a canonical loop — read inbox, execute the work,
respond — with one iteration per inbox batch. The agent stays parked between
batches and wakes up only when there's something to do, instead of composing
ad-hoc polling logic itself.

The broker skill has been rewritten around this pattern. Older recipes for
Monitor-streaming and standalone wait-for-reply loops are gone; Broker Mode is
now the canonical way to drive a long-running collaboration.

## `broker recv` replaces `broker follow`

`broker follow` is gone. The replacement, `broker recv`, returns a single
batch of messages and exits, which is the shape Broker Mode actually needs.

**Behavior change:** the old `--idle-timeout` flag is removed. `broker recv`
takes `--timeout` (max wait for the first message) and `--burst-window`
(post-first-arrival drain window, default 5s). Once the first message lands,
`recv` keeps draining until the burst window goes quiet, then returns
everything it collected.

**Foot-gun:** presence is now scoped to a single `recv` call. An agent is
"live" only while a `broker recv` is in flight; between iterations of Broker
Mode the agent appears `offline` in `who` / `broker clients`. This is
intentional — presence reflects who is actually listening at that instant —
but it does mean a parked Broker Mode agent will not show up as live until
its next iteration begins.
