# Upcoming

## Commands replace explicit-invocation subskills

Ten workflows that only ever ran on explicit user request have moved from skill subdocs to slash commands. They're now invoked by name instead of competing for context every session:

- `/skill-cefailures:brain-style:review` — architecture review of a file/function/class (previously the "brain-review" subskill).
- `/skill-cefailures:brain-style:claude-md` — review or author a project's `CLAUDE.md` (previously the "claude-md" subskill).
- `/skill-cefailures:documentation-sync:setup` — set up the Documentation Sync section in a project's `CLAUDE.md` (previously a subskill of documentation-sync).
- `/skill-cefailures:permissions-auditor:install` — install the permission-logging hook (previously a subskill of permissions-auditor).
- `/skill-cefailures:permissions-auditor:analyze` — analyze and triage logged permission requests (previously the main subskill of permissions-auditor).
- `/skill-cefailures:broker:setup` — first-time broker setup walkthrough.
- `/skill-cefailures:broker:mode` — enter Broker Mode (replaces the old `/broker-mode` command).
- `/skill-cefailures:broker:send` — send a DM, broadcast, or reply-all.
- `/skill-cefailures:broker:read` — drain the inbox or peek at history.
- `/skill-cefailures:broker:doctor` — diagnose broker setup (5-point health check).

The `permissions-auditor` skill is fully removed — its two workflows are now commands. The `broker` skill is pared to a namespace stub: its shared reference docs (`critical-rules`, `signals`, `authority`, `troubleshooting`, `usage`, `patterns`) remain under `skills/broker/docs/` and are read by the broker commands directly. The `brain-style` and `documentation-sync` skills have shorter descriptions and slimmer routing tables. The old `/broker-mode` command is gone — use `/skill-cefailures:broker:mode` instead.
